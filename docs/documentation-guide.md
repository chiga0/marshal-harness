# 文档维护与发布

## 各文档的责任

| 文档 | 唯一责任 |
| --- | --- |
| README 与站点首页 | 产品定义、价值、适用对象、边界和阅读入口 |
| 愿景、架构、生命周期、安全模型 | 完整目标系统及其职责、保证、取舍和不变量 |
| 标准 API、扩展契约、OpenAPI | 系统边界、交互语义、数据与错误、版本和兼容要求 |
| Milestone | 从基线走向目标的实施出口与验收要求 |
| Roadmap、发行记录、版本支持 | 具体候选的实现、启用、验证和发行事实 |
| ADR、历史快照 | 决策理由、取代范围和历史证据 |

目标设计不嵌入临时进展，README 不复制 Milestone；版本说明不能改写架构目标。目标合同的完备性按端到端职责和失败处理判断，不以接口数量判断。具体平台绑定需要独立合同，不通过一句“可插拔”获得执行权限。

## 变更与证据

改动产品目标时同步愿景、架构与对应契约；改变信任边界、持久化、生命周期或发布权限时新增或替代 ADR。只整理现有决定不创造新状态或运行许可。

历史记录保留原候选和结论。当前设计不要求读者逐份拼接旧报告；被替代的正文明确归档，当前入口给出完整叙述。实现支持与实际验收分别记录，未知计量不填零，未测不写通过。

## 本地构建

在仓库根目录执行：

```sh
python3 -m venv .marshal/docs-venv
.marshal/docs-venv/bin/pip install -r requirements-docs.txt
.marshal/docs-venv/bin/python scripts/prepare-docs.py
.marshal/docs-venv/bin/mkdocs build --strict
.marshal/docs-venv/bin/python scripts/check-docs-site.py
```

构建目录在 `.marshal/`，不进入业务提交。发布页面由 `mkdocs.yml` 的导航及生成的 HTTP 参考组成；其他历史或源码链接转换到构建提交对应的 GitHub 文件。OpenAPI 下载由唯一机器定义逐字复制，不维护第二份手写 Schema。HTTP 操作与 Schema 参考也从该文件生成。

PR 执行相同构建和站内文件／片段链接核验；每次 main 更新均验证并发布 Pages，避免非文档提交使旧构建跳过后没有后继部署。构建信息记录来源提交和 OpenAPI 摘要，部署成功不自动等于文档中的产品声明正确。

## 文档验收

- 产品入口能解释用途、适用场景、边界与上手入口，且不夹带施工状态。
- 架构覆盖正常交付、拒收、取消、恢复、未知外部结果及扩展责任，并解释取舍。
- 标准契约覆盖输入、输出、授权、错误、幂等、版本和接纳规则；概念接口与真实可调用接口明确区分。
- 每条版本能力声明能追溯候选、实现或独立证据；不借文档完善扩大运行保证。
- 站点构建、导航、站内文件及片段链接通过；OpenAPI 下载与源文件字节相同。
- 独立 reviewer 检查准确性；如改变产品 UI，另按 UI 三线验收，不以文档站检查替代。
