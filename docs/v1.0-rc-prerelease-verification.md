## 为什么不能迁移为 RC1

1. `commit=unknown`，没有冻结 exact sourceHead、build date、toolchain/profile与 current canonical object。
2. 旧四平台集合不是 [ADR 0068](adr/0068-mac-first-cli-only-lifecycle-preview-rc1.md) 的 RC1 支持面；RC1 只支持 unsigned Darwin arm64 CLI-only `darwin-local-dogfood` preview，Linux/server/其它架构不能成为其发布证据。
3. 旧资产没有 S1′→S2′→Attach/rebind→terminalization 的 fixed CLI authority 链，没有真实 Pi + 独立 ReviewDecision `ACCEPTED`，也没有同一最终 bytes 的 host viability、canary、安装与恢复闭合。
4. 当时记录的 lease、ResultIngress、binding 与真实 Pi 缺口是历史快照；其中部分 component 后来已演进，不能继续作为当前权威状态。当前状态只以 [v1.0 Release Readiness 判定表](v1-release-readiness.md) 为准。
5. 旧 lightweight `git tag v1.0.0-rc1`、`git push` 后自动发布和旧 version 输出期待均已撤销。ADR0068要求的RC1 release/installer guard尚未实现；在其落地并经审查前，不存在替代命令，也不得虚构一个。
