# 执行透明度、工作台与从零验收

本批目标：用户不需要读取 hash 或私有数据库，就能理解任务阶段、成员工作、阻塞、策略与成果；交付前由研发方消化可复现的功能与交互缺陷。基线 `80f6fed5203b8b6c52c3add0d3852a7ca512b6cf`。本文先冻结验收，结果另行追加，不以案例存在表示通过。

## 产品出口

1. 工作台：哪些任务需要我、哪些正在执行、哪些已有成果。计数注明加载范围。
2. 任务工作台：目标、当前阶段、当前焦点、阻塞及下一步；阶段取自真实状态与执行事实，不制造进度百分比。
3. 成员详情：工作目标、Agent/模型来源、执行耗时、实际输入、公开活动/工具记录、输出与用量。技术身份默认折叠。
4. 策略与成果：展示原 Leader 决定、独立 Review 意见及验收依据的可读正文，绑定原证据；不通过另一个模型猜测原因。
5. 运行中静默不能称为思考；只在 Provider 明确报告时显示相应活动标签，不保存隐藏推理正文。未报告模型/Token/费用明确显示缺失与覆盖。
6. 实际输入只表示 Marshal 交给 Agent 的内容，不能声称包含 Agent 自有系统提示、Skill 或完整模型上下文。披露为明确受信策略，有界并标注脱敏/截断；不恢复任意披露回调。

所有正常案例使用无敏感合成资料、同一通用文件配置。输入与预期在任务开始前冻结；不修改需求迎合输出。真实模型失误与人为故障分别记录。每次记录候选、安装包/页面摘要、任务 ID、耗时、干预、模型调用、重试/返工及失败原因；用量缺失不填零。

## 控制与异常案例

| ID | 操作 | 断言 |
| --- | --- | --- |
| F01 | 运行中取消 | 原操作收口，所属执行清理，无替身或虚假交付；页面说明实际停止状态 |
| F02 | 正常停开、刷新、丢失一次操作响应 | 同根读取原事实，原键重放同回执，不自动重新创建/批准；令牌不进入URL、存储或截图 |

| F05 | 工具范围、用量、输入披露反例 | 注册与实际工具事件分别检查；未知工具不放宽；累计用量不重复计；敏感字段不无差别公开；prepared不冒充handed-off |

## 可理解性与视觉检查

所有S/M/C案例都通过页面检查：当前阶段、谁在执行/等谁、最近策略、问题原因、下一步、最终成果位置。成员输入必须是实际记录，不用计划目标冒充。终态停止运行动画；陈旧观察注明时间。

浅深主题覆盖1440/1024/375px及200%缩放；检查运行、待答、失败、交付、长中文、长ID、无用量。整页不横滚，主操作可达；键盘可开关成员详情、操作确认及返回；刷新不抢焦点、不把读旧记录的滚动位置拉到底。截图来自实际实现，受控状态与真实模型分别标注。

## 执行与收敛

三个完整研发包并行：可靠交付接缝、执行透明度数据链、任务工作台。共享合同先审，独立worktree/单写者，集中集成后独立审查，不按字段拆PR。

先明确构建UI，再从冻结候选打包/核验；新settings、安装目录、私有数据根与独立端口，不改用户现有launcher、设置或运行服务。模型登录沿原Agent使用，不复制凭据。浏览器创建/回答/批准/下载，API仅作只读断言；受控故障单独允许测试拦截，记录真实服务响应。

先跑确定性回归，再S→M→C真实模型；失败定位后修复并复测影响范围，不盲目重跑。最终候选S01连续3次、M01连续2次、C01一次，S02/M02及控制异常各有对应证据。所有失败留在分母。该门槛是有限样本验收，不能承诺绝对没有未知缺陷。

功能可靠性、视觉交互和Agent模拟走查由研发方完成，不把简单问题交给用户反复发现。按既有三线规则，真人可用性只能由未参与开发的目标用户/代表完成；未执行如实保留，不冒充PASS，也不阻止继续完成全部可自动与模拟验证的工作。
