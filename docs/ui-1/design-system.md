# UI-1 设计规范

## 视觉方向

参考 Multica 的紧凑任务工作台、可调侧栏、语义 Token 与当前执行优先的结构。Marshal 保持任务交付主轴，不复制其工作区/团队管理规模。以下为首版基准，视觉评审可微调具体色值，不能各页自行发明体系。

## 主题 Token

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| app-bg | #F6F7F9 | #111318 | 外壳 |
| surface | #FFFFFF | #191D24 | 正文、面板 |
| surface-muted | #F0F2F5 | #222833 | 次级区块 |
| text-primary | #17202E | #F1F4F8 | 正文 |
| text-secondary | #536174 | #AEB9C8 | 辅助文字 |
| border | #DDE2E9 | #394352 | 分隔 |
| accent | #1D4ED8 | #93B4FF | 选中、焦点、操作 |
| success | #166534 | #86EFAC | 验收成功 |
| warning | #92400E | #FCD34D | 待处理 |
| danger | #B91C1C | #FCA5A5 | 失败、危险操作 |

背景与前景成对定义，按钮前景不能默认全是白色；深色 accent 按钮采用深色文字。状态柔和底色单独定义，不以透明度削弱正文可读性。上述色值不是对比度已通过证据，开发交付必须逐对验证。

字体：系统中文无衬线，不依赖外网字体；正文 14px/22px，宽松正文 15px/24px，辅助 12px/18px，标签 13px/20px，页标题 22px/30px，区块标题 16px/24px；代码系统等宽。间距使用 4/8/12/16/24/32px，圆角 6/8/12px，边框 1px。阴影只用于浮层，不把全部信息卡片化。

## 布局

1440px 基准：导航 224px，正文自适应，右栏默认 320px、允许 280–480px 调宽；正文最小宽度不足时收起右栏。1024px 下默认折叠侧栏；768px 以下导航和 Worker 详情改抽屉。375px 下主操作可见，整页不横向滚动；代码/表格允许自身滚动。200% 缩放保留全部操作。

列表行以标题、状态、最近进展/等待、更新时间为主；不展示空费用和无意义百分比。详情标题、当前状态、待处理卡片位置稳定。多个问题按 deadline 与出现时间排序，不能用颜色作为唯一优先级提示。

## 组件清单与状态

| 组件 | 必须处理的状态 |
| --- | --- |
| AppShell/连接面板 | 未连接、就绪、401、服务断开 |
| TaskList/分页 | 首次加载、空集合、局部搜索无匹配、加载失败、还有下一页 |

| WorkerPanel | 运行、待答、结束、观察陈旧、无日志 |

| AuditTimeline | 分页、重复事件去重、断线、长内容 |
| ErrorNotice | 错误正文、可执行恢复动作、技术详情折叠 |

## 内容、安全与可访问性

中文界面，保留 Task/Worker/Artifact 技术引用用于详情；默认用「任务」「执行成员」「成果」。主按钮具体命名，如「确认并开始」「回答问题」「允许本次发布」。破坏性操作二次确认只针对取消等有实际影响动作，不在查询/下载上加审批。

焦点清晰、Tab 顺序正确、抽屉 Escape 关闭并还原触发焦点；输入有 label，错误关联到字段；异步状态用适度 aria-live，日志追加不抢焦点或强制滚底。所有功能可键盘操作。正文对比度目标 4.5:1，大字与控件边界 3:1；触摸主要目标至少 44px。减少动态效果时停用非必要动画。

Markdown 默认禁止原始 HTML 和脚本协议，外链显式打开；不自动加载远程图片泄露任务内容。首版预览限有界纯文本/安全 Markdown，HTML、SVG、脚本等只下载，不同源执行。错误/日志不得包含 token；截断内容提供展开或下载，不悄悄遗漏授权正文。

## 视觉交付

开发者提供浅深两套的列表、详情、待确认、待授权、失败与空状态截图；记录 viewport 和候选 SHA。截图必须来自实现，原型不能替代。审查关注信息层级、长中文/长 ID、键盘与窄屏；不用主观「像 Multica」作为验收标准。
