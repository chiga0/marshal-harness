# 安全模型与权限边界

本文定义 Task-first、`trusted-single-user` 服务的安全目标和责任。实际平台、Provider和执行配置的保证以[支持矩阵](api-support.md)和[Roadmap](roadmap-status.md#业务交付当前表)为准。产品职责分离、证据权威与操作系统隔离是不同保证，不能互相替代。

## 信任假设与保护资产

操作者信任所选Agent/模型、受信组合代码和业务材料，服务面向可信单用户任务。Leader、开发、Reviewer、验收与发布是产品职责，不是不同OS安全主体。同UID进程可能访问原生登录、HOME、凭据助手、本地服务及其他文件；过滤环境、限制回调、工作目录和本地token都不能证明这些资源不可达。

保护范围包括原始业务输入、源码与成果、Task事实和授权、秘密、宿主资源、模型预算及真实外部效果。即使材料来自可信项目，文本也不能作为控制指令扩大权限；构建脚本、工具和依赖本身可能执行代码，部署方必须按实际风险选择执行环境。

恶意代码、多租户、强凭据隔离、敌对插件和无人值守不可信负载不属于可信单用户保证。需要这些保证时必须取得对应环境的独立强制与测试证据；不能只改profile名称或提示词。普通本地子进程永不宣传为恶意代码沙箱。

## 权威与语义边界

| 主体 | 权威范围 | 不能据此获得的能力 |
| --- | --- | --- |
| 用户 | 提供目标、必要业务判断及精确批准 | 通过自然语言绕过机器合同或创造缺失的执行能力 |
| Leader | 提出有界业务建议和整体判断 | 改预算/权限/证据，直接操作Store或执行handle |
| Core | 校验并持久接纳事实、批准、原预算和执行义务 | 宣称确定性理解任意自然语言，采信作者自证 |
| Worker | 在批准范围产出候选与实际报告 | 自授发布、签发自身权威验收、修改检查标准 |
| Review / Verification | 对绑定候选提供独立意见或程序检查 | 覆盖真实失败，替代不同性质的必需检查 |
| Publisher / 外部适配 | 执行精确获准动作并提供实际观察 | 用角色名或原生登录扩大目标范围，直接裁决Task成功 |

输入、Skill、仓库指令、模型摘要、工具输出和远端回执都要按来源及用途接纳。Prompt injection不能改变已批准计划、资源范围、验收标准或发布权限。Core只解析闭集有限动作，不执行模型生成的控制代码。

## 最小授权与受信扩展

默认没有业务发布授权。计划批准、普通答案、工具回调、安装Skill和已登录Agent均不是发布批准。外部写需要受信目标实现、精确目标/操作/成果/证据/期限授权，以及执行前的当前性检查。软件tag/release/签名与业务发布是不同权限，不复用一次Task确认。

Agent保留原生登录和Skill管理；Marshal不复制HOME、搜集凭据或通过清登录改变宿主安全策略。Skill描述能力，不授予执行权；连接器可用不代表其中每个工具都对当前Task开放。受信组合与执行/工具准入限制任务能力，但宿主进程可能存在的旁路必须明确披露，不能说提示中的禁令覆盖所有原生工具。

扩展代码由部署方显式安装和配置，不接受HTTP或模型上传可执行函数。进程边界减少耦合，不自动形成安全沙箱；受信进程内DI也不适合运行任意敌对插件。新Agent必须满足任务所需的协议、输入、停止和观察能力，未知或缺失时拒绝所需动作，不静默降级。

## 本地访问与数据边界

服务数据默认位于产品根 `$HOME/.marshal-node/`；仓库研发的worktree、日志和缓存位于忽略的 `.marshal/`，两者互不接管。Git忽略只防误提交，不是访问控制。数据、日志、连接信息和临时文件采用受限权限，制品不得收集服务秘密、内部运行态或目录外内容。

本地HTTP默认loopback，认证token经受保护连接文件交给客户端，不放URL、Task、Worker环境或普通日志。Host/Origin检查、请求大小/时间/深度与有界响应共同限制本地入口；localhost不等于无需认证。远程访问不能直接复用“本机可信”的前提，须另有身份、传输和权限合同。

任务目录一个写入者；Git写任务锁定base并使用独立worktree，非Git任务使用独立执行目录。路径、符号链接、特殊文件、大小和摘要在采集/交付时检查，未知归属不能复用目录。工作目录隔离只保护任务组织和误操作，不阻止同UID恶意访问其他路径。

秘密仅在授权组件确有需要时使用，不进入prompt、事件、日志、成果或摘要材料。记录实际提交输入的披露范围和不可取得部分，不记录隐藏推理；metadata-only不能被宣传为保存了全部原始正文。自托管仅控制Marshal权威状态的位置，模型与工具调用可能出域，须按对应Provider核验。

## 执行归属与资源限制

Execution只操作已取得真实归属的handle，不能从磁盘PID重构停止权限。start许可、Attempt、原预算与输入绑定；退出、结果接纳与cleanup是不同事实。取消或期限先封闭新派发，再停止原所属执行；停止Agent不等于停止其已经创建的远端作业。

Task与全局资源额度均生效，Leader/Review/验证/发布/后验也计入。长等待、沉默或heartbeat不能刷新硬期限；未知token/费用不填零或伪退款。超过能力或结构不合法应在付费调用前拒绝，不能原样无限重试。

Store不可写或owner丢失时可按预批准安全规则停原live handles，但不得伪造停止回执。未确认清理或效果未知时保持相应占用/限制，不用“业务已结束”释放假空槽。

## 独立证据与发布完整性

作者不能为自身成果提供唯一权威证据。Review绑定原需求、完整候选和实际输入；Verification从精确独立成果运行可信检查，结果绑定原ticket、policy、摘要和当前选果。变更输入、答案、依赖或候选后重查适用性，不用旧绿色检查为新成果签字。

程序断言可能遗漏业务要求，模型Review也可能误解；因此要检查需求覆盖、错误候选反例及必要的用户判断。多模型或多轮投票不自动证明独立或正确。Leader总结只能引用已接纳事实，不能覆盖失败或必需未测项。

发布许可前持久化精确意图和可查询身份；执行后保存真实回执。外部创建成功但回执未提交时，恢复读取原意图并lookup，匹配、冲突、absent或unknown各自处理，不盲重发。只有具体合同证明未获许可及目标确未产生等安全条件时才可继续原动作，不能泛化成所有远端系统exactly-once。

独立后验读取真实目标并验证业务期望。后验失败保留已发生效果；取消不自动回滚；补偿需要独立授权与证据。默认产品自动merge禁用，不从历史SCM合同推导Node已支持任意Draft PR或生产写。

## 存储、升级与恢复

每根一个权威owner，关键事件/投影/预算/幂等/outbox同事务接纳；外部I/O在事务外。输入及成果按摘要引用，事件摘要用于一致性与绑定检查，不宣称同UID攻击者重写整个库后仍能由库内摘要独立证明未篡改。

新根与旧格式分开；不支持格式在claim前拒绝，不隐式迁移或重签旧记录，不清空损坏数据库来恢复“成功”。配置变化必须按已接受升级合同显式处理；活跃或归属未知执行不被新启动器接管。备份恢复保存完整事实，却不能自动回滚外部平台，也不提供多写或防分叉保证。

旧终态和幂等回执保持原解释。已提交决定恢复原动作，未提交调用只有在原合同、真实清理和原预算允许下有限继续；旧代结果不能改绑。具体custody与never-permitted资格由原ticket协议和受信实现证明，不由Agent品牌、v7标签或远端自报资格决定。

## 扩展到更强环境时必须证明什么

访问许可和隔离强度是两个独立问题：获准只读不代表进程不能写；远程也不代表更安全或更不可信。任何新环境必须具体说明文件、网络、凭据、子进程、资源与外部工具的强制边界，以及谁观察并证明这些边界。

要求强隔离的任务不能降格到普通宿主进程后继续。环境证据需绑定实际实现/配置与有效范围，由独立检查取得；过期或失效时拒绝依赖该保证的执行。历史hardened设计可用于追溯，但不能用旧枚举充当现行Node支持声明。详见[扩展合同](extension-contracts.md)和[历史安全参考](security-model-reference-2026-09-14.md)。

## 验收与供应链责任

发布前验证影响范围内的认证/Origin、路径与秘密、作者自证、旧摘要、幂等冲突、取消/迟到、owner/磁盘故障及外部unknown负例。真实模型业务、确定性夹具、隔离证明和软件发行证据分开报告；未测不写通过。

受信代码、运行依赖、Agent入口与配置身份需要可追溯；运行中不得静默更新Provider或改变策略。发行消费者校验原包、签名与manifest，兼容和恢复在同版本资产上验证。具体签名方式按[ADR0096](adr/0096-node-stable-asset-signing-minisign.md)及资产类别，不把纯JS包称为Mach-O公证，也不以业务发布授权豁免软件发行门禁。
