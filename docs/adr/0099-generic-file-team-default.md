# ADR 0099：默认通用文件团队与分层验收

- 状态：Accepted（2026-09-10，用户明确接受“独立 Agent 审查内容 + 固定程序核验实际交付文件”，先跑通通用文件交付；实现与实机验收尚待完成）。
- 范围：Node trusted-single-user 的无业务配置本地启动；不授予外部业务写权限。

## 决定

接入与默认团队装配属于产品代码，不属于 Skill。`init` 发现、记录支持的本机 Agent 路径，不启动模型、不改登录；`serve` 在没有显式业务配置时选择内置通用文件团队。已有显式配置优先，不覆盖配置、不迁移或重解释已有 Store。默认团队使用专用数据根及现有 v7 Application/SQLite，不创建新状态机。发现 executable 不等于协议、登录或实机能力通过；运行失败必须如实报告。

默认能力是基于 Task 需求和上传材料，受管 Leader 规划有界文件分工，独立执行的作者产出文件，另一受管 Agent 审查真实内容，固定 Node checker 核验精确文件、布局、摘要和完整交付。复用已有 generic-files layout、Leader/Review、FileBusiness、Verification receipt、取消与恢复；不把区域报表模板改名冒充通用任务。

## 验收含义与精确调整

本范围具体化 ADR0094 的独立语义审查，并限定调整 ADR0095 的“独立最终验收”：文件类自然语言需求由独立模型 Review 判断覆盖与内容，确定性 checker 证明实际交付 bytes 和完整性。两者均为必需证据，且绑定当前需求/计划/选果；作者及 Leader 的自报通过不成立。程序不宣称能够证明任意自然语言语义正确，模型审查也不承诺零错误。

交付范围必须在计划批准前明确：只交付文件，不证明文件中的 SQL 已执行、代码已部署、数据已发布或补数完成；这些外部效果仍需独立配置授权与可核查回执/验收。超范围要求应澄清或拒绝，不能把“完成文件”报告成原外部目标成功。默认 publication 为 null，不允许模型请求扩大权限。

## 执行与兼容

- Provider 品牌接入留组合/Adapter 层，Core 不写死品牌。优先接入已发现 Qwen ACP，不增加精确版本白名单，也不声称其他 Adapter 已完成默认团队验证。
- 每角色不同受管执行、独立目录/会话。文件权限按实际协议闭集检查；未知工具、shell、网络、SQL/MCP 外部操作默认不允许，不删除现有 extraScope fence。
- 复用原 native 登录及模型配置，不复制 HOME、搜集凭据或启用安全绕过。普通同 UID 执行不是恶意代码隔离。
- 初始动态计划不承诺自动 repair；保留有限原预算，Review 拒绝即非成功，不无限付费重试。
- 原 HTTP、已有 profile、发行资产和历史 Outcome 不变。默认选择仅作用于无显式配置的新默认根；冲突/损坏/未知旧根拒绝，不清空重建。

## 验收出口

同一默认配置至少完成两种不同文件需求的真实 HTTP/Qwen 团队交付及下载；覆盖内容拒收、摘要漂移、越界/多余文件、取消和冷开无重复执行。机器测试与真实模型证据分别记录。未完成前不得宣称新版开箱即用或 DataAgent ETL 生产验收通过。

## 实机反馈：收尾事实必须可见

第二次实测发现：Core 已保存 `leader.delivery` 与 `stage=finalizing`，但 Leader 冻结输入只含历史摘要、不含这些现有事实，后续通知仍为 `delivery-ready`，导致重复 `deliver`。本决定补充 ADR0095 的内部 Leader 输入：新调用的 snapshot 显式携带当前 stage 与 delivery，二者仍来自唯一 durable Core，不接受 Agent 自报或新增状态机。它们与完整输入一同绑定摘要；原已冻结 ticket、输入摘要和历史证据不回写、不重算。

Leader 在交付已记录后应根据原 Review/验收总结 `conclude`，不是再次交付；Core 对新发起的重复 `deliver` 拒绝。原命令的耐久幂等查找与恢复语义不变，不把相同命令恢复误判为新的重复动作。提示文本只是解释事实，不替代授权、currentness、独立审查及验收检查。
