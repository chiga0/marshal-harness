# ADR0097：Node 22 及以上按实际能力接纳

- 状态：Accepted（2026-09-10，依据用户在已知 Node22 SQLite defensive 差异后明确要求实施 Node22 及以上兼容）。
- 范围：Node trusted-single-user 实现的运行环境准入；不改变旧 Go profile、HTTP、SQLite 格式、执行生命周期或发布授权。

## 决定

将 ADR0088 §6 的固定 Node 运行时约束调整为：Node 主版本至少22，不设大版本上限；启动前检查实际需要的 SQLite 能力。版本符合不等于全部功能可用，更不等于所有未来版本已经验收。CI 保留精确版本用于可重复测试，发行 manifest 的 `node` 继续表示原构建/验证基线，不重写旧发行清单。

必要能力包括精确 BigInt 读取、可观察事务状态、事务提交/回滚和外键约束；在内存数据库检查，失败在创建或打开业务状态前拒绝并给出具体原因。Node22早期缺少内置SQLite或所需行为时，不回退JSON、不安装原生addon、不静默更换数据库。

`defensive` 是纵深增强：支持时保持开启，不支持时如实报告能力及警告，而不是因未知选项未抛错就声称已启用。Node22.22.1确实不提供此保护；当前Store数据库句柄私有，只执行固定内部SQL、业务值通过参数绑定，不开放任意SQL或扩展加载。这不是恶意同UID隔离，亦不是任意SQL执行权限。未来若增加任意SQL或依赖defensive的业务路径，须重新评估，不继承本次兼容授权。

## 验证与发行

- 对 Node22.22.1 与24.15.0运行关键Store、HTTP、团队、取消和恢复回归；Linux/macOS CI分别记录结果。新发现的不兼容可以收窄范围，但不能伪报未测试版本已通过。
- 不以删除测试代替兼容：测试断言业务语义，历史候选字节与source/digest校验保留。
- 已签名v1.0.0原包内部仍有24版本门禁，不修改它、不在安装时热补丁。兼容源码形成新发行包后，安装器才切换相应签名/摘要；源码合入不等于新包已发布。
- 不自动升级或替换用户的Node/Qwen，不修改系统默认PATH、Agent登录及Skill。

## 成本与边界

接受较宽准入带来的未来兼容风险，以实际能力错误与回归定位问题；不为兼容性引入新服务、状态机或版本管理平台。保留独立验收、事务/幂等、路径权限、默认发布拒绝和秘密保护。
