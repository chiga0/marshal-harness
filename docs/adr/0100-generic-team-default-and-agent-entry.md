# ADR 0100：通用团队默认入口与可执行 Agent 接入

- 状态：Accepted（2026-09-14；用户明确要求修复非通用装配及 DataWorks Qwen 入口；独立审查 `a0f3333d` 无阻塞意见后由维护者接纳，不代表实现或发行已完成）。
- 基线：`ac286399e8859207a3a61a9bcf710cc6de58c485`。
- 关联：ADR0085、ADR0094、ADR0095。安装成功、通用文件交付、外部业务完成分别验收。

## 问题

发行包把限定地区汇总配置作为主要可运行示例；通用布局没有接入默认服务。Qwen 工厂要求 npm 包名和 `cli-entry.js`，拒绝合法的 DataWorks `bin/qwen`。这不是用户配置错误。协议兼容不能由特定文件名或版本名单代替；示例 oracle 不能成为所有任务的业务限制。

## 决策

1. 通用装配复用唯一 Application、v7 Leader、Review、FileBusiness、VerificationCommand、SQLite、原预算及取消恢复；不创建另一个状态机。用户只改变需求、输入、计划确认，不能在 HTTP 上传可执行配置。
2. 默认成果模式为小型 UTF-8 文件：合法动态作者/依赖与一个汇合 verifier，输入和上游按摘要注入，成果独立收集。独立模型 Review 检查原需求与完整候选；固定数据检查器核对实际文件集合、UTF-8、非空、大小、摘要及交付完整性，不执行作者代码，也不把结构正确说成任意业务正确。交付含原成果而非仅摘要。
3. 受信 Leader 策略的 repair 增加可选 `scope: 'plan-authors'`，同时要求 `nodeIds: []`。计划冻结时派生该计划全部 author ID并展示在验收条款；每次修正从已批准同计划重新核对范围，仍需绑定真实独立意见/失败、当前结果、原预算与最多一轮。省略 scope 的旧静态 ID 语义逐字保留，不把空旧列表重新解释。策略摘要改变时旧服务根拒绝配置漂移，不迁移旧记录。
4. 可执行 ACP 工厂直接接收受信绝对可执行入口并封闭传入 `--acp`，复用真实受管 initialize/session/prompt 协议；不限定 npm 布局或精确版本。固定路径验证和真实进程归属仍保留。未启动/握手不宣称登录和模型可用；不从目录名推断品牌。凭据由 Agent 原生管理，不搜索、复制或输出。
5. `serve` 没有显式或已记录业务配置时选择随包通用配置和已发现/显式指定 Agent。默认新数据目录与历史示例根分开；记录选择与连接。已配置的服务不被静默替换，活跃服务与请求配置不一致时提示重启，不杀未知进程、不清空数据库。UI 地址取真实启动输出，与内部客户端连接地址分开。

## 权限与业务范围

默认只授权冻结输入的读取和成果文件写入，非 OS 沙箱；Agent 原生登录或自动批准配置可能具有 ambient 权限，不能宣传隔离。不得默认批准 shell/MCP/生产 SQL/发布/补数据，也不删除 `acp_tool_scope_unproven`。

任意发现的 ACP 入口不自动取得 custody 恢复资格：默认 `eligible:false`，当前 owner 的正常执行及取消按真实观察收口；冷崩溃后可能进入 `intervention`，不能以文件工具白名单推导全部原生工具都可安全冷恢复。

本次通用文件模式不提供真实 ETL 完成承诺。外部任务的后继闭环必须有操作范围/授权、耐久意图、外部操作 ID、只读结果核查、unknown 禁止重发、独立后验；不得把外部写藏在 author 阶段绕过既有发布职责。该后继能力单独冻结合同并实施，不能以文件报告冒充平台回执。

## 验收与发行

- 同一装配完成两种不同意图及不同节点名/依赖的文件任务；真实 API 提交、确认、独立 Review、验证、下载和正常重开。
- 非法路径、额外/缺失文件、过大/非 UTF-8、未通过 Review、陈旧修正/未批准节点、未知工具请求不能成功；原取消、预算、重复提交及恢复不退化。
- DataWorks 风格可执行入口无 npm 目录依赖；受控 ACP 正负例先行，真实 DataAgent 环境验证仍需用户实机结果，不借本机普通 Qwen 证据外推。
- 安装→init→serve→客户端自动连接及随包 UI 在新发行原字节上验收；旧配置/版本/状态保留。真人产品可用性与 fixture/浏览器技术验证继续分列。
- 新版本只有实测通过的范围可声明，不能把该改造称作通用外部发布已实现。
