# ADR 0034：Qoder CLI Live Conformance Authority 与可撤销准入

- 状态：提议（Proposed）——在维护者接受、本 ADR 的负向矩阵通过独立审计且真实 credentialed probe evidence 被外部 authority 签发前，Qoder CLI 不得宣称当前部署 `supported`
- 日期：2026-08-17
- 关联：[ADR 0003](0003-separate-worker-and-publisher.md)、[ADR 0004](0004-independent-verification.md)、[ADR 0018](0018-control-plane-and-provider-ports.md)、公开 Issue #137

## 上下文

Qoder CLI Worker Adapter 已能以版本、realpath 和 executable digest 固定本地进程，但 hermetic fake、`--version` 或 Adapter 自报都不能证明真实 credential、冻结 `stream-json` 协议、权限画像和仓库写入行为可用。生产注册若只读取一个布尔开关，会让 Worker 为自己提供准入证据；若把一次校验永久缓存，又会绕过 evidence 撤销、key rotation 与 host 替换。

本 ADR 冻结的是 **AgentAdapter 本地准入证据**，不是 ADR 0018 的 Sandbox Provider `ConformanceEvidence` authority-ledger 对象。两者不得互换、复用 digest 或被描述为同一 assurance。

## 决策

### 1. 三方职责

1. 独立 verifier 在无业务仓库权限的隔离 scratch worktree 中运行真实 credentialed Qoder probe，采集 typed observation；Qoder Worker、Adapter 与 fake fixture 都不能产生权威通过结论。
2. authority signer 只签发 verifier 已裁决的完整 observation。签名者不运行 Qoder、不读取 credential、不写 Marshal 状态；私钥不进入 Marshal 进程、配置、日志或仓库。
3. Marshal consumer 只持有 Ed25519 public trust root，逐次验证完整 evidence、目标 executable 与当前 host。配置者、Worker 输出、CapabilitySnapshot 和 transcript 自报都不能替代 authority signature。

probe-only verifier 只能输出 canonical、封闭且无敏感信息的 typed observation document；它不持 receipt authority 或 evidence authority private key，也不能调用 evidence signer。它只持固定 policy 指定的独立 verifier attestation key，对完整 observation（含四份 receipt 正文与摘要）签名。独立 authority signer 必须从自身固定 trust policy 重新验证 verifier key identity/signature、receipt authority key identity/signature、四份 receipt chain 与精确 candidate identity 后才封装 evidence 签名，禁止替 observation 填入期望 contract。ADR 为 Proposed 时 exported verifier/signer 均 typed hard-disabled，调用者不能注入自己的 keypair 建立新 trust anchor。observation 必须逐项携带实际值：runner/version、observedAt/validUntil、adapter/Qoder CLI version、Qoder realpath/digest/binary version、完整 host attestation identity、authority generation、suite/probe artifact/challenge digest、capability/profile/argv/environment/tool-policy digest、event/protocol/permission contract、transcript/receipt digest、receipt/verifier key identity，以及 credential/live-protocol/scratch-worktree-write 三项 verdict。任一缺失、错误或 `false` 都拒绝签发；evidence 中这些字段必须逐项复制 observation，不得由 signer 注入常量或把 verdict 改写为 `true`。

三类签名 key 分别属于 `receipt` / `verifier` / `evidence` role，任两类不得复用 private key。独立 operator 维护 append-only `QoderProbeTrustKeyRecord` ledger；record 的 `additionalProperties=false` exact schema 为 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderProbeTrustKeyRecord`、`schemaVersion=1`、`ledgerEpoch`、`role`、`keyId`、`keyEpoch`、`operation=activate|revoke`、`publicKeyEncoding=base64url-unpadded`、`ed25519PublicKey`、`publicKeyDigest`、`previousRecordDigest`、`effectiveAt`、`operatorKeyId`、`operatorKeyEpoch`、`operatorSignatureAlgorithm=Ed25519`、`operatorSignatureEncoding=base64url-unpadded`、`operatorSignature`、`recordDigest`。首条 `previousRecordDigest=null`，其余必须精确连接紧前 record；`activate` 的 key 必须是全局未使用的 `(role,keyId,keyEpoch)`，`revoke` 必须复用已 activate 的精确 public identity，且最多一次。operator key 来自独立、只读、OS-owned trust config，不能由 receipt/verifier/evidence signer 改写。未知 key、角色串用、断链、回滚、同 epoch 异 digest、撤销后新签名均 fail closed；只有在撤销前已被 consumer high-water 精确锚定的历史链可重放审计。

operator、host-attestation provider 与 consumer-fence provider 三个根角色另由 OS `QoderOSTrustAnchorProvider` 维护不可由 Marshal/Qoder 删除或倒退的 monotonic `QoderOSTrustRootRecord` ledger。record 的封闭 schema 精确包含 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderOSTrustRootRecord`、`schemaVersion=1`、`trustDomainId`、`rootSequence`、`role=trust-ledger-operator|host-attestation-provider|consumer-fence-provider`、`keyId`、`keyEpoch`、`operation=activate|revoke`、`publicKeyEncoding=base64url-unpadded`、`ed25519PublicKey`、`publicKeyDigest`、可空 `previousRecordDigest`、`effectiveAt`、`anchorProviderIdentity`、`anchorProviderCounter`、可空 `authorizingKeyId`、可空 `authorizingKeyEpoch`、可空 `authorizationSignatureAlgorithm`、可空 `authorizationSignatureEncoding`、可空 `authorizationSignature`、`recordDigest`。首条记录的 previous/authorizing/signature algorithm/encoding/value 五项为 null；后续五项必须非空，algorithm/encoding 固定为 `Ed25519` / `base64url-unpadded`，并由仍有效的上一 root key 使用 domain `marshal-qoder-os-trust-root-v1\0` 签名完整 record digest。

OS provider 返回的 `QoderOSTrustAnchorReceipt` 封闭 schema 精确包含 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderOSTrustAnchorReceipt`、`schemaVersion=1`、`anchorProviderIdentity`、`trustDomainId`、`rootSequence`、`rootRecordDigest`、可空 `previousRootRecordDigest`、`anchorProviderCounter`、可空 `previousAnchorReceiptDigest`、`observedAt`、`providerKeyId`、`providerKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`、`recordDigest`，使用 domain `marshal-qoder-os-trust-anchor-v1\0` 签名。root record 的 `recordDigest` 移除 `authorizationSignature/recordDigest`，anchor receipt 的 `recordDigest` 移除 `signature/recordDigest` 后执行本 ADR 的 JCS digest；签名一律覆盖 domain 加完整 digest ASCII bytes。OS provider 对 `(trustDomainId,rootSequence,rootRecordDigest,previousRootRecordDigest,anchorProviderCounter,previousAnchorReceiptDigest)` 做 compare-and-advance 并幂等返回同一不可回滚 receipt；root record 的 counter 必须与 receipt 相等。本地 ledger 或 receipt 删除、旧 snapshot、同 sequence 异 digest、跳号、旧 key 复活均 fail closed。每个新 root key 必须先由仍有效旧 root 与 OS anchor receipt 共同授权；首个 root 只能由 provider signed genesis 建立。operator/provider root 轮换必须提升 authority generation、撤销旧 evidence、重跑 probe；平台不能提供该 monotonic continuity 时保持 unsupported。`osTrustRootLedgerTailDigest` 必须被 trust policy、evidence 与 authority config 同时绑定。

#### 1.1 签名 record 与 canonical 算法

以下 record 均为 `additionalProperties=false`，所列 member 全部 required；只有显式标注可空的 member 能编码 JSON `null`。下文 `/` 只用于并列书写、表示两侧是两个独立 member，不能作为 JSON member 名或省略任一侧。raw JSON 先递归拒绝 duplicate member、尾随非空 JSON、未知/缺失 member 与错误类型，再用仓库唯一 `internal/canonical.JSON` / `canonical.DigestJSON` RFC 8785 JCS 实现验证 canonical bytes。所有 digest 是小写 `sha256:<64-hex>`；所有 `*Epoch`、`*Sequence`、`ledgerEpoch`、`authorityGeneration`、`providerCounter` 是 `0..2^63-1` 的 JSON integer；时间是 UTC、零小数或九位纳秒小数的 RFC3339 字符串；ID/版本/枚举是长度 `1..256` 的无 NUL UTF-8 string；Ed25519 public key 解码后精确 32 bytes，signature 解码后精确 64 bytes。所有 array 都有下述固定 cardinality/order/uniqueness，object 的 nested schema 也必须按下述定义封闭；byte/string/array/object 上限由 schema 固定，不能由调用者扩大。

公共 nested object 只有三种：`CandidateExecutableIdentity` 精确为 string `realpath`、uint64 `device/inode`、digest `digest`、semver string `binaryVersion`；`RootIdentity` 精确为 uint64 `device/inode` 与 digest `identityDigest`；`IsolationAudit` 精确为 string `auditProviderIdentity/auditSessionId`、digest `launchAuditDigest/denialAuditDigest/exitAuditDigest/ancestorChainDigest`、与 `businessRootIdentities` 相同 cardinality/order 且逐项绑定对应 root 的 `businessRootDenialDigests`，以及 boolean `credentialReadOnlyEnforced/businessRootsDenied/scratchOnlyWriteEnforced/networkPolicyEnforced/ambientStateDenied`。`actualArgv` 是 `1..64` 项、每项 `1..4096` bytes 的 string array；root identity array 按 canonical bytes 严格递增且不重复，digest/revoked digest array 按 digest ASCII bytes 严格递增且不重复；除明确为四变体的 array 外其余 array 最大 `256` 项。`eventContract/protocolVersion/permissionMode` 是非空 string，不是自由 object；三项 verdict 与所有 `*Enforced/*Denied` 是 JSON boolean。

- `QoderProbeExecutionReceipt`：`apiVersion=marshal.dev/v1alpha1`、`kind=QoderProbeExecutionReceipt`、`schemaVersion=1`、`receiptId`、`probeRunId`、`receiptSequence`（精确 `1..4`）、`variantId`、`probeRunChallengeDigest`、`variantChallengeDigest`、可空 `previousReceiptDigest`、`candidateExecutableIdentity`、`actualArgv`、`actualArgvDigest`、`replacementEnvironmentDigest`、`scratchRootIdentity`、`credentialRootIdentity`、`businessRootIdentities`、`isolationProfileDigest`、`topologyDigest`、`hostIdentityDigest`、`isolationAudit`、`sessionId`、`modelId`、`protocolVersion`、`permissionMode`、`eventContract`、`transcriptDigest`、`markerDigest`、`startedAt`、`completedAt`、`receiptAuthorityKeyId`、`receiptAuthorityKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`、`recordDigest`。sequence 1 的 `previousReceiptDigest=null`，2..4 精确连接上一份 receipt；四份 receipt 必须共享 `probeRunId/probeRunChallengeDigest`，variantId 按 profile 固定顺序且不得重复。receipt 中 root identity 不含绝对路径；environment 不携带原始 value。
- `QoderLiveConformanceObservation`：`apiVersion=marshal.dev/v1alpha1`、`kind=QoderLiveConformanceObservation`、`schemaVersion=1`、`observationId`、`probeRunId`、`runnerId`、`runnerVersion`、`observedAt`、`validUntil`、`adapterVersion`、`candidateExecutableIdentity`、`hostIdentity`、`authorityGeneration`、`suiteDigest`、`probeArtifactDigest`、`probeRunChallengeDigest`、`capabilitiesDigest`、`profileDigest`、`argvDigest`、`environmentDigest`、`toolPolicyDigest`、`eventContract`、`protocolVersion`、`permissionMode`、`transcriptDigest`、按 `receiptSequence=1..4` 的精确四份 `executionReceipts` 与精确四项 `executionReceiptDigests`、`aggregateReceiptDigest`、`credentialVerified`、`liveProtocolVerified`、`workspaceWriteVerified`、`receiptTrustLedgerTailDigest`、`osTrustRootLedgerTailDigest`、`verifierKeyId`、`verifierKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`、`recordDigest`。`aggregateReceiptDigest` 是 ASCII domain `marshal-qoder-receipt-aggregate-v1\0` 后按 sequence 拼接四个完整 receipt digest ASCII bytes所得的 SHA-256；observation 中 receipt 正文的 canonical digest 必须与数组逐项相等。
- `QoderConformanceEvidence`：`apiVersion=marshal.dev/v1alpha1`、`kind=QoderConformanceEvidence`、`schemaVersion=1`、`evidenceDigest`、`observationDigest`、`probeRunId`、`runnerId`、`runnerVersion`、`observedAt`、`validUntil`、`adapterVersion`、`candidateExecutableIdentity`、`hostIdentity`、`authorityGeneration`、`suiteDigest`、`probeArtifactDigest`、`probeRunChallengeDigest`、`capabilitiesDigest`、`profileDigest`、`argvDigest`、`environmentDigest`、`toolPolicyDigest`、`eventContract`、`protocolVersion`、`permissionMode`、`transcriptDigest`、精确四项 `receiptDigests`、`aggregateReceiptDigest`、`credentialVerified`、`liveProtocolVerified`、`workspaceWriteVerified`、`receiptTrustLedgerTailDigest`、`verifierTrustLedgerTailDigest`、`evidenceTrustLedgerTailDigest`、`osTrustRootLedgerTailDigest`、`evidenceAuthorityKeyId`、`evidenceAuthorityKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`。上述与 observation 重合的 member 必须 canonical-value 逐字节相等，signer 不得重算或改写；签名 key 必须以 `(role=evidence,keyId,keyEpoch)` 唯一选择。
- `QoderAuthorityConfig`：`apiVersion=marshal.dev/v1alpha1`、`kind=QoderAuthorityConfig`、`schemaVersion=1`、`repositoryIdentity`、`authorityGeneration`、`hostIdentityDigest`、`evidenceRootIdentity`、`currentEvidenceDigest`、`probeArtifactDigest`、`probeRunChallengeDigest`、`revokedEvidenceDigests`、`trustPolicyDigest`、`receiptTrustLedgerTailDigest`、`verifierTrustLedgerTailDigest`、`evidenceTrustLedgerTailDigest`、`osTrustRootLedgerTailDigest`、`consumerFenceProviderIdentity`、`configDigest`。`repositoryIdentity` 与 `consumerFenceProviderIdentity` 是 ID string，`evidenceRootIdentity` 是 `RootIdentity`，四个 ledger tail 与 current/probe/challenge/config 都是 digest。

receipt/observation 的 `recordDigest` 完全移除顶层 `signature` 与 `recordDigest`，trust-key record 的 `recordDigest` 完全移除顶层 `operatorSignature` 与 `recordDigest` 后调用 `canonical.DigestJSON`；evidence 的 `evidenceDigest` 完全移除顶层 `signature` 与 `evidenceDigest`，config 的 `configDigest` 完全移除自身后使用同一算法。签名消息分别是 ASCII domain separator `marshal-qoder-receipt-v1\0`、`marshal-qoder-observation-v1\0`、`marshal-qoder-evidence-v1\0`、`marshal-qoder-trust-key-v1\0`，拼接对应完整 digest 的 ASCII bytes；禁止直接签 JSON、hex decoded bytes 或平台字符串。

### 2. 精确绑定

- host 绑定不使用 hostname、OS/arch、MAC 或调用者传入字符串。独立 OS `HostAttestationProvider` 在 verifier 与 consumer 均可测量的 trust domain 提供 `HostAttestationIdentity`：exact schema 为 `apiVersion=marshal.dev/v1alpha1`、`kind=HostAttestationIdentity`、`schemaVersion=1`、`providerIdentity`、`hostKeyId`、`hostKeyEpoch`、`hostPublicKeyEncoding=base64url-unpadded`、`hostPublicKeyDigest`、`osAttestedMachineIdentityDigest`、`os`、`arch`、`issuedAt`、`previousHostIdentityDigest`（初始为 null）、`providerKeyId`、`providerKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`、`recordDigest`。`recordDigest` 移除 `signature/recordDigest` 后使用本 ADR 的 JCS 算法，provider 签名消息为 ASCII `marshal-qoder-host-identity-v1\0` + 完整 ASCII recordDigest；provider key 来自 OS-owned 只读 trust config。`hostIdentityDigest` 精确等于该 recordDigest，receipt authority 在每个 variant 执行时测量并签入 receipt，verifier/signer 原值传递，consumer 在每次 `Probe`/launch 用当前 OS attestation 重测，doctor 只公开 digest/key id/epoch。变更 host key、machine identity 或 provider identity 都是 reprovision：必须提升 authority generation、撤销旧 evidence、重跑四变体 probe；禁止把旧 host 证据当成 rotation continuity。平台无法提供不可由 probe/Qoder 进程伪造的 machine attestation 与 host-key possession proof 时保持 unsupported。
- probe profile 必须冻结真实 argv 模板、完整替换环境、空 setting sources、`accept_edits`、无 session persistence、空 named Worker tool allowlist 与隔离 scratch worktree 写入。`argvDigest` 绑定由运行时同一个 `buildArgs` 模板机械生成的四种真实组合：model 省略/存在 × `--tools` 省略/显式空值；任何未进入该矩阵的 TaskSpec argv 都必须 fail closed。probe 不拥有业务仓库权限不等于不能验证 workspace-write。
- verifier 不得根据 request 或预期常量自行产生三项通过 verdict。隔离 sandbox 必须以固定 policy 锚定的独立 Ed25519 receipt authority 对每轮实际执行签发 canonical、closed `QoderProbeExecutionReceipt`，逐项绑定 held executable fd 的 device/inode/digest、实际 argv、完整替换 environment、held scratch/credential/write/deny root identities、执行时 topology、同一 probe run/chain identity、variant challenge、transcript/session/model/version/protocol/permission、marker 与执行时间。receipt authority 只能在 OS launch audit 成功、credential 强制只读、全部业务 root deny、scratch-only write、network policy 与 ambient-state deny 均有外部 audit 后把 `IsolationAudit` 五项 boolean 写为 true，并绑定对应非敏感 audit digest；缺一项即拒绝 receipt。verifier 只持 receipt public key，逐项与持续持有的 invocation handles 和实际 transcript/marker/audit 对账；`hermetic-fixture` receipt、调用者自带 key、未知/缺失字段、签名错误、任一替换、断链或跨 run/variant replay 都不能生成可签名的 live observation。authority signer 重新验证四份 receipt chain、所有 audit digest/boolean 与 aggregate，不能只信 verifier 三项 verdict。
- evidence 的最大 validity window 与最大 observation age 均为 24 小时；更长窗口、未来时间、过期或陈旧记录 fail closed。
- authority config 精确绑定一个 current evidence digest、probe artifact digest、probe-run challenge digest 与递增 authority generation，并可列出 revoked evidence digests。相同 key 的新 generation 不改写旧 evidence。
- consumer 必须在独立于只读 authority root 的 consumer-owned 私有目录中耐久维护 generation ledger，并使用另一 OS-owned、consumer 不可删改的 `ConsumerFenceAnchorProvider` 维护 monotonic initialized/high-water anchor。本地 exact layout 固定为 `qoder-authority/initialization.json`、`qoder-authority/generations.jsonl`、`qoder-authority/high-water.json`；initialization 精确绑定 `consumerInstanceId/repositoryIdentity/fenceProviderIdentity/providerGenesisDigest`，并与 provider 的 signed genesis 相等。prepared/committed generation record 精确绑定 transaction、ledger/generation、完整 config/host/trust identity、previous record、provider receipt 与 recorded time，high-water 绑定最后 committed record 与 provider monotonic counter/receipt digest。三者均使用封闭 schema 与本 ADR 的 canonical/detached 算法。安全解析 config 并验证 trust/authority/host 边界后，顺序固定为 local prepared append+fsync → provider monotonic compare-and-advance → local committed append+fsync/high-water atomic replace → 解析 current evidence leaf。crash 只以绑定同一 transactionId 和 prepared record digest 的 provider receipt 补齐同一 generation，不会倒退、跳过或串用另一 transaction。
- fence record 同样使用 `additionalProperties=false`：`QoderConsumerFenceInitialization` 精确包含 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderConsumerFenceInitialization`、`schemaVersion=1`、`consumerInstanceId`、`repositoryIdentity`、`fenceProviderIdentity`、`providerGenesisDigest`、`createdAt`、`recordDigest`；`QoderConsumerGenerationRecord` 精确包含 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderConsumerGenerationRecord`、`schemaVersion=1`、`transactionId`、`state=prepared|committed`、`ledgerEpoch`、`authorityGeneration`、`configDigest`、`previousRecordDigest`、`hostIdentityDigest`、`trustPolicyDigest`、可空 `providerAdvanceReceiptDigest`、`recordedAt`、`recordDigest`，`prepared` 时 provider digest 必须 null，`committed` 必须非空、紧跟同 transaction prepared 且 `previousRecordDigest` 精确等于该 prepared record digest；`QoderConsumerFenceHighWater` 精确包含 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderConsumerFenceHighWater`、`schemaVersion=1`、`consumerInstanceId`、`repositoryIdentity`、`ledgerEpoch`、`authorityGeneration`、`configDigest`、`generationRecordDigest`、`providerCounter`、`providerAdvanceReceiptDigest`、`updatedAt`、`recordDigest`。provider signed genesis/advance receipt 的 exact common 字段为 `apiVersion=marshal.dev/v1alpha1`、`kind=QoderConsumerFenceGenesisReceipt|QoderConsumerFenceAdvanceReceipt`、`schemaVersion=1`、`providerIdentity`、`consumerInstanceId`、`repositoryIdentity`、`providerCounter`、`transactionId`、可空 `preparedRecordDigest`、`authorityGeneration`、可空 `configDigest`、可空 `previousReceiptDigest`、`observedAt`、`providerKeyId`、`providerKeyEpoch`、`signatureAlgorithm=Ed25519`、`signatureEncoding=base64url-unpadded`、`signature`、`recordDigest`；genesis 的 transactionId 固定为 `genesis`、prepared/config/previous receipt 为 null、generation/counter 为 0，advance 的三项均必须非空并逐字节绑定 request 的 transactionId、prepared record digest、generation、config、expected previous receipt 与 next counter。分别使用 domain `marshal-qoder-fence-genesis-v1\0` / `marshal-qoder-fence-advance-v1\0`。provider 对相同 transactionId+prepared digest 幂等返回同一 receipt，对任一字段不同的重用 fail closed；commit 与 recovery 只接受该精确 receipt。
- provider genesis 已存在后，本地 initialization/ledger/high-water 任一缺失、删除、截断、断链、snapshot rollback 或与 provider 不一致都 fail closed；只有 provider 证明从未初始化时才可创建 genesis。更小 generation，或相同 generation 下替换 evidence/probe artifact/revocation/trust/host 等任一 config identity，均 fail closed。平台无可验证 OS monotonic anchor 时保持 unsupported，不得以单个可替换 JSON 文件降级。
- 耐久 fence 目录必须是绝对 clean path、逐段 `openat(O_NOFOLLOW)` 打开的当前 uid/root-owned `0700` 真实目录，并与 authority signer 的只读 evidence root 处于独立故障域。consumer 必须同时持有 fence dirfd 与后续实际解析 evidence leaf 的同一个 authority dirfd，以 device/inode identity 和双向祖先遍历拒绝同目录、路径别名、fence-under-authority 与 authority-under-fence，不能重开路径或只比较路径字符串。consumer 以精确 `0600`、owner-only、single-link regular lock file + OS advisory exclusive lock 串行化跨线程/跨进程消费；精确 `0600` 的记录通过同目录随机 `O_CREAT|O_EXCL|O_NOFOLLOW` 临时文件、file `fsync`、`renameat`、directory `fsync` 原子提交。重启只读取已提交的封闭版本记录；损坏、超限、未知字段、异常类型/权限、锁争用都 fail closed，残留临时文件不构成 authority。

### 3. 文件与路径边界

`MARSHAL_QODER_CONFORMANCE_CONFIG`、authority root 与 evidence leaf 必须是绝对 clean path。consumer 从 `/` 开始逐段使用 dirfd + `openat(O_NOFOLLOW)`，不跟随任何父级或 leaf symlink；leaf 用 `O_NONBLOCK` 打开并在读取前 `fstat`，FIFO/device/socket 均不得阻塞或伪装。config/evidence 必须是当前 uid 或 root 拥有的私有 regular file，authority root 必须是当前 uid 或 root 拥有且权限 `0700` 的真实目录。JSON 拒绝未知字段并执行严格字节上限；digest 命名 leaf 只通过已打开的 authority root dirfd 解析。

generation fence root 是 Marshal consumer 的本地耐久状态边界，不得由 evidence signer 写入、不得与 evidence root 相同或互相嵌套，也不得携带 credential、private key、config path、evidence 正文或 transcript。ADR 为 Proposed 期间该 root 仅由同包 hermetic candidate 测试显式注入；未来生产启用必须由 Marshal 应用 state 配置提供，不得从 authority config 自行选择、覆盖或间接别名到可写路径。

### 4. 撤销、恢复与可观察性

ADR 0034 为 Proposed 时，生产 `NewFromAuthorityConfig` 必须无条件返回 typed permanent conformance-pending，应用不得注册 Qoder；候选 consumer 只能由同包 hermetic test 驱动。ADR 接受本身也不自动启用，必须由独立后续变更在矩阵与真实 evidence 均通过后显式移除硬禁用。

未来启用的生产 Adapter 不把一次成功变成永久内存授权。每次 `Probe` 和每个 Worker launch guard 都重新安全读取 current config、trust roots、generation、revocation set 与 content-addressed evidence，并重新验证签名、freshness、profile、host 和 executable identity。删除、撤销、权限变化、key rotation、generation rollback/identity 漂移立即使当前操作 fail closed；长寿命 `marshal-server` 无重启豁免。

当且仅当上述逐项复核通过时，CapabilitySnapshot/doctor 才可报告 `supported`，并公开非敏感的 evidence digest、trust-root key id、profile digest、validUntil、host fingerprint 与 authority generation，便于 ReviewPacket 和运维审计精确绑定。不得输出 config 路径、credential、private key 或 transcript 正文。

### 5. 验证与启用门禁

负向 fixture 至少覆盖：生产硬禁用、缺失配置/evidence、未知字段、duplicate member、错误 JSON type/array cardinality/order/重复项/超限、非 canonical 数字/字符串、过期/未来/超长 TTL、完整 observation 缺失与逐字段替换、错误 executable realpath/digest/version、同 OS/arch/hostname 但 host attestation 不同、host key/provider/operator rotation/reprovision 未重做 probe、旧 OS trust-root ledger/snapshot rollback、错误 suite/artifact/probe-run/variant challenge/profile/argv/env/tool policy/event/protocol/permission、跨 run receipt 拼接/断链/错 sequence/aggregate、缺失或 false 的 isolation audit、任一 verdict 为 false、receipt/verifier/evidence key 角色串用、同 keyId 错 epoch、未知/轮换/撤销 key、错误 domain/encoding/signature length、generation rollback/同代替换、已撤销 digest、config/root/evidence symlink（含父级）、FIFO、错 owner/权限、运行中撤销后 Probe 与完整 `Run` launch 拒绝，以及 supported-Qoder Schema/doctor metadata 必填。generation fence 另须覆盖进程重启与独立进程 rollback、本地 initialization/ledger/high-water 删除或截断、文件系统 snapshot rollback、provider anchor 落后/冲突、prepared/provider-commit/local-commit 每个 crash 点、receipt transaction/prepared digest 替换与重复 transactionId 冲突、同代 identity 冲突、并发消费、临时文件残留、损坏/超限/未知字段记录、root/lock/record symlink/FIFO/非精确 `0600`/hardlink、同目录、双向嵌套、路径 alias 以及 commit 后重开恢复。

CI 中生成的 key、fake executable 和 synthetic transcript 只能验证 canonical/signature/fail-closed 机制，必须明确标记 hermetic fixture；它不构成真实 live evidence，不改变当前部署状态。只有独立外部 probe 的真实 evidence 被运维配置并在当前 host 通过 doctor 后，该 host 的 Qoder 才可参与调度。

候选 verifier 不提供普通宿主进程 fallback：它必须使用独立 OS principal 与强制隔离的 `QoderProbeIsolationProfile`。profile 精确要求：Qoder/probe process 不持 receipt/verifier/evidence private key；只读精确 credential capability；唯一可写 capability 是当轮 scratch worktree；业务仓库 root 对 `open/openat/rename/link/unlink/mount/chdir` 及等价 pathname/fd/capability 路径全部由 OS 强制拒绝；禁止继承 ambient environment/fd/session/agent socket；network 只能到 policy 锁定的 Qoder service identity。receipt authority 运行在 sandbox 外的独立 principal，从 provider 的 launch/denial/exit audit 与 held handles 生成 receipt，不接受 sandbox/Qoder 自报的“denied”布尔值。Linux 与 macOS 可使用不同 OS 机制，但必须通过同一 capability/syscall/path/credential/network denial 语义矩阵；与目标 Qoder 相同 UID/普通 subprocess、仅 chdir/chmod、仅容器标签或仅 topology 观察均不构成隔离。平台无法提供可独立验证的强制 denial 时 fail closed/unsupported。

该 profile 运行四种真实 argv 组合，sandbox 的唯一写域是 verifier-owned scratch，并显式拒绝全部业务仓库 root；环境为完整替换且 observation 没有 credential、stderr、transcript 正文或 private key 字段。`1.1.23` fake fixture 仅约束解析、capability/profile/argv 和 signer fail-closed 机制，不得标记为 credentialed live probe。

候选 verifier 从 `/` 逐段 `openat(O_NOFOLLOW)` 打开并在整个 probe 期间持有 executable、scratch root、credential root 与全部业务仓库 root；按 device/inode 与双向祖先拒绝 alias、同目录及任一嵌套，sandbox 只能消费这些 held handles/identity，不能重开 request path。每轮 scratch 只用 `mkdirat/openat` 创建并持有 dirfd。challenge marker 只从该 dirfd 以 `openat(O_NOFOLLOW|O_NONBLOCK)` 打开，读取前 `fstat` 并要求当前 uid/root-owned、精确 `0600`、single-link regular file、严格 byte limit；symlink、FIFO、device、oversize、hardlink 与 path swap 均 fail closed。路径 rename/swap 不会改变已绑定 identity，后续 consumer 仍会以 realpath+digest 拒绝漂移。

静态 held identity 不足以裁决动态拓扑。verifier 在每个 variant 执行前、sandbox 返回后及 marker 读取后重新遍历全部 held dirfd 的双向 ancestry，要求 scratch 仍位于 held scratch root 内且 credential/business roots 与 scratch 始终分离；receipt authority 另行绑定 sandbox 执行时计算的同一完整 ancestor-chain digest。pre/receipt-at-execution/post 任一点不一致即 fail closed；执行中把 credential/business root rename/nest 到 scratch 后再 swap-back 不能逃逸。

启用顺序不可压缩为一个变更：（1）本 ADR 经独立评审 P0/P1 清零并由维护者接受；（2）只落地独立 isolation/receipt/verifier/signer tooling 与负向矩阵，production consumer/registry 仍硬禁用；（3）在目标 host 产生真实 credentialed 四变体 evidence，由非作者复核 receipt/observation/evidence 精确 identity、secret scan 与跨平台 conformance；（4）单独 consumer enablement 变更才能移除 `NewFromAuthorityConfig` 硬禁用，并须在 required Linux/macOS CI、secret scan、当前 host doctor 与撤销/回滚演练全绿后注册 supported Qoder；（5）最后才能改变新 Worker 调度优先级。任一步失败均保持上一步的 hard-disabled 状态，ADR 接受、tooling CI 或一份 synthetic evidence 均不能跳步。

## 后果

- Qoder 可以在不向 Marshal 暴露 credential 的前提下获得可审计、短期且可撤销的本地准入。
- 每次 Probe/launch 会增加少量私有文件读取和签名验证成本；安全撤销优先于缓存命中。
- 本 ADR 为 Proposed 时实现只能作为候选机制，不能据此关闭 Issue #137 或宣称 Qoder 已完成 live conformance。
