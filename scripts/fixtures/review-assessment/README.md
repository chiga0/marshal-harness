# 逐项评审的冻结组件案例

基线 `8086b8a1972193e983cd26959322e28e2e0dc2fe`。本目录保存精确差异与评测口径；完整材料由生成器从已授权的合成任务 Audit 输入只读提取，保存在忽略的 `.marshal/`，不提交原会话材料。不读取原生隐藏推理、不调用模型、不创建 Task。

## 准备与边界

用 Node 24 执行：

```sh
node --test scripts/review-assessment-cases.test.mjs
node scripts/review-assessment-prepare.mjs /absolute/evidence-directory /absolute/new-private-suite-directory
```

来源必须是 `1eccece1a2168dc5b9dafbb640d1fa286b15d375` 的 `S02-1eccece1-1`、`C01-1eccece1-1`。生成器核对原 Audit 摘要、实际最后一次 Review 输入与最终交付正文相等。负例保持输入原样；正例只修改最终候选指定片段，保留原 Task、三个附件、批准计划业务内容、回答和未改动的上游材料。正例材料、合成 result/manifest、selection、readSet 中 selected 引用与 input 摘要重新计算；它们是组件引用，不能提供 Core 权威。

新目录仍为 `PENDING_TRUSTED_HELPER`。不能把新政策伪称为旧 Task 已批准内容；后续由受信 helper 生成独立组件的新增验收目录，并分别保存原输入摘要与新组件输入摘要。当前 suite 使用独立 profile，旧运行脚本不能直接当正式旧 suite 运行。

标签与预期只在 suite 外层。模型只能收到经过受信接入的 `input`；运行工作目录及 ticket ID 必须随机不透明，不包含 S02/C01、positive/negative 或预期 verdict。后继实际调用要经过原受信 Review Port/receipt，原输出、结构校验与业务结论分别记录；这里没有模型调用入口。

## 四例口径

| 案例 | 仅候选变化 | 预期 |
| --- | --- | --- |
| S02 原失败 | 原2969字节 HTML 不变 | `rework`，政策依据是未确认安排不得冒充既定事实，不是禁止所有创作 |
| S02 修正 | 介绍中的现场流程改为建议；日程附近标出具体环节与分段时间待确认；报名入口只查看说明，实际渠道未知 | `accept`，限定文本事实/建议边界，不声称真实报名服务可用 |
| C01 原失败 | 原5599字节最终 JSON 不变 | `rework`，清单已写而索引未建的恢复判定缺失 |
| C01 修正 | 补完成判定、失败重建分支、相应验收和回退跳过条件 | `accept`，限定文本设计闭合，不声称已实现并测试知识工具 |

S02 的原用户请求明确授权写介绍、日程和报名区，新增拟议日程本身不是错误。拒收依据必须显式来自执行前配置政策；新增事实不能只因与已知事实不矛盾就通过。正例保留所有原区块、日期时间地点与顶部 `#signup` 锚点，不要求额外后端，不把所有阅读交流文案判为未授权。不得将页尾“示意”或仅出现“建议”关键词当作合格：要看相关承诺处是否清楚区分已知、拟议和未知。

C01 原附件明确幂等导入与回退，候选自身又承诺两步任一步失败重跑等价，因而检查该窗口不是追加目标。正例不要求特定数据库、字段名或备份体系；明确先保存待完成清单，完整重建临时索引并替换后才标记完成，只在完成且一致时跳过。来源不变是本样例边界；来源不匹配须报告失败，不伪造恢复。工具内新增标签已由原任务修复稿收敛为仅提取原笔记标签，本组件不能再套旧标签丢失反例。原上游材料保留为历史分析，最终交付以最后选中的整合稿为准。

## 可观察验收

- S02：逐段核对原已给事实与候选陈述；具体分段安排须在日程区标示拟议，报名区不得声称到场即获准。HTML 锚点、区块及375/1440实际展示可以另由受信浏览器消费者验证；本文的字符串变换测试不冒称渲染已通过。
- C01：用含唯一词和标签的 A.md，初态清单/索引无 A；在清单落盘而索引未建时失败，按候选写出的规则重跑，应补成一个可检索 A，标签匹配；再跑不增加记录。另检查索引替换后完成标记前失败；前后原笔记摘要应一致。这里只审方案中这些分支及前提是否已定义，真实工具实现后才执行故障注入。
- `unknown`：候选缺关键设计分支要求返工；缺用户才能提供且任务必需的事实要求澄清，不让作者猜造。方案交付未运行软件本身不应自动判 unknown。没有找到问题仅说明本轮有限审查结果，不是通用语义正确性证明。
- 结构判定：原引用逐字真实不保证推论正确；只有非空理由或出现“幂等/事务/建议”不能通过。四例预期是独立业务审查标签，生成测试不证明模型会给出正确结论。
