    Agent Team 实施 Milestone¶

    本页定义走向目标架构的实施出口和验收要求。实际完成状态、精确候选与证据只在 Roadmap维护；版本支持说明可使用范围。阶段目标不因某个版本通过而删除，也不以历史状态文字重新开启已完成工作。

    路线与依赖¶

    阶段 用户出口 主要退出依据
    B1 团队 PoC 提交需求、批准计划，真实团队自主完成可消费成果 同一候选的真实执行、独立整体验收、下载消费、取消与正常重开
    B2 日常 API 本地简启动、问答、控制、成果、审计及恢复可日常使用 唯一 Application/SQLite、真实驱动、完整生产调用链
    B2-L 受管 Leader 从需求到批次结果、Review、局部修正、授权交付和后验的完整协调 精确决定/证据/回执，原预算内闭环，不靠人工逐节点推进
    API-STABLE 检查点 客户端有明确可依赖的合同 指定操作/Schema/版本及支持条件的兼容与消费证据
    B3 正式发行 声明平台上可安装、长期运行、故障可处置 同资产安装、恢复、平台验证、适用签名及受保护发行
    UI-1 界面交付 用户能完成真实任务并理解结果 功能可靠性、视觉交互、真人产品可用性三线分别通过

    核心 API-STABLE 后 UI 可并行推进，不阻塞正式 API 发行。UI 未完成不撤销既有 API 范围的证据。B3 软件发行与 Task 的业务发布是不同出口。

    B1：真实团队交付¶

    必须同时证明：

    1. 从真实 HTTP 输入和明确交付约定开始；两个有互补职责的作者真实并行，有执行时间证据。
    2. 服务自主调度、收集、集成与独立验收，不由人逐 Run 推进；所有证据绑定同一精确候选。
    3. 下载实际成果并在独立位置消费；两个分支各自合法但组合错误的反例不能成功。
    4. Task、Worker、失败原因、成果和已知耗时可查询；未知用量不填零。
    5. 取消或期限只停止所属执行；停止未知时不得复用目录；重复请求不启动替身。
    6. 正常重开保留计划、决定和成果，不重复执行；不能安全恢复时明确停止和保存失败。
    7. 不依赖 Workspace 注册、三品牌齐全、UI 或历史治理 Skill。Git 任务锁定 base 并使用独立 worktree，非 Git 任务不伪造仓库。

    B2 与 B2-L：同一服务完整闭环¶

    • 接入：安装、Agent 发现/配置、真实协议握手、连接与任务创建均有真实出口；原生 CLI 可执行不等于模型可调用。
    • 需求与计划：只澄清影响结果、成本或权限的歧义；同一配置接受不同需求及 DAG，不要求每次编写专用业务程序。
    • 团队：共享上下文进入实际工作包；独立 Review 检查原需求和完整候选；验证器在作者之外检查业务断言。
    • 修正：有真实拒收依据，只重做受影响闭包，保留无关成果；不能换任务清零预算或降低验收。
    • 交付：阶段验证、交付、授权发布、后验和整体结束分别计证。生成文件不能充当平台发布回执。
    • 控制：问答只阻塞相关依赖，pause 阻止新派发；Task/Worker cancel、期限、所有权失效和晚到结果有明确行为。
    • 恢复：唯一 Store 中决定、预算和 outbox 一致；已提交行动恢复原记录，外部 unknown 查询原操作，不盲重发。
    • 可观察性：用户能知道在等谁、缺什么、为何采取行动、外部效果是否发生；观测不替代权威证据。

    至少包含正常真实任务、执行前已存在的真实缺陷修复、受控故障与协议反例三类证据。不得让正常作者故意犯错以制造修正成功。一个 Provider 多实例可证明协作；更多驱动逐项证明能力，不以品牌数替代闭环质量。

    API-STABLE 与 B3¶

    接口检查点必须绑定具体 OpenAPI 字节、操作与 Schema 集合、运行配置、客户端和候选版本。新增操作不得自动继承旧检查点。至少核对：

    • OpenAPI、handler、客户端、示例与错误形状一致；未知字段、陈旧 revision、重复 key 和不同正文重放有明确拒绝。
    • 请求接纳、业务完成和终态分别可观察；缺能力如实失败，不以路由存在代替支持。
    • 输入上传、成果下载及审计能在独立客户端完整消费，秘密不进入日志和制品。
    • 正常重启和关键冷故障、取消竞争、磁盘故障、owner 漂移、晚到结果按声明范围验证。
    • 所声明 Node/OS 组合消费同一发行资产；长期样本公布实际持续时间、失败与限制。
    • 按资产类型执行签名与分发验证；不适用 Mach-O 公证的脚本包说明理由，不机械增加不适用门禁。
    • 升级保留旧安装、配置与数据；配置身份变化不静默迁移或复活旧任务。

    业务扩展出口¶

    一个业务族的端到端交付作为一个完整工作包，使用扩展契约接入。

    工作包 独立退出条件
    通用文件团队 同配置不同需求/分工，原始需求Review、实际文件核验、下载消费；不冒充执行文件中的代码
    外部业务（例如 ETL） 精确操作范围/授权、耐久意图、外部 ID、重复提交语义、查询核对、独立业务后验；unknown 禁止重发
    非 CLI Agent 能力准入、真实执行身份、结果收集、取消/断连/恢复与清理的完整责任；不能只证明 HTTP 可调用
    更强执行隔离 环境实际限制文件、网络、凭据和工具；不能以角色名或提示词作为强制证据

    具体平台接入不得放宽已有任务、权限和恢复不变量；改变持久化、生命周期或授权合同须先有 ADR。通用外部任务不因文件模式通过自动获得完成资格。

    UI 三条独立验收线¶

    按照 UI 验收规范，分别记录候选、范围、证据、结论和缺口：

    • 功能与可靠性：自动化检查及真实服务操作，fixture 与真实 Agent/业务证据分开。
    • 视觉与交互：真实浏览器、截图、点击、键盘、缩放和动态刷新。
    • 产品可用性：未参与开发的目标用户或代表完成指定任务；Agent 模拟和代码 review 不替代真人。

    按影响范围验收；不适用须独立 reviewer 确认，缺证据记待验。合并或预发布不等于完整 UI 验收。

    并行交付与收益判断¶

    先冻结共享目标、契约与验收，再按独立 scope 分配完整工作包。各写任务使用锁定基线和独立 worktree；共享模块一个写入者，集中集成、并行独立审查。包内尽早跑通生产调用链，不等最后才集成，不按字段拆微 PR。

    报告业务完成率、实际耗时、人工介入、等待、retry/rework 和用量来源。保留失败分母；比较单 Agent 和团队时使用同等需求、模型、工具及验收。质量相当却增加耗时和干预时，优先减少无收益流程。
