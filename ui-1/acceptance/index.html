    UI-1 验收目标与 E2E 场景清单¶

    本文件定义持续适用的验收要求，不承载当前运行结果。初稿（2026-09-10）场景均为 NOT_RUN；实际结果见各批次验收记录，不因本规范更新而自动通过。实现时由独立验收者在冻结候选执行，作者自检不能作为最终通过。

    三条独立验收线¶

    2026-09-11 用户明确要求：后续所有 UI 变更均按以下三条线验收，互相不能替代。适用于页面、组件、文案、导航、主题以及影响 UI 的 API/状态/配置变更。

    验收线 必需方法与范围 不能替代的证据
    功能与可靠性 相关自动化测试＋真实服务操作；核对操作结果、状态、错误、取消、重连/恢复和结果不确定时不重复提交。按变更影响选择场景 组件 fixture 或 CI 全绿不能代替真实服务流程；确定性 Provider 不冒充真实 Agent
    视觉与交互 真实浏览器截图＋实际点击、键盘、缩放；检查层级、密度、长内容、溢出、焦点、反馈、刷新跳动；按影响覆盖深浅主题、桌面/窄屏、空/加载/有数据/失败/陈旧状态 截图不能代替交互；空页不能代替真实任务、运行中 DAG；DOM 断言不能代替视觉检查
    产品可用性 未参与该流程开发的目标用户或代表，在尽量不指导的情况下完成指定任务；记录找入口、理解状态、选择下一步、辨认交付结果时的困难 独立代码 review、开发者自测或 Agent 模拟走查不能冒充真实用户可用性验收

    真实产品页面始终使用服务实际数据；样例、随机进度及 mock 不得作为失败回退或演示填充。隔离测试允许明确标注 fixture，但不得把其截图/指标混入真实业务证据。

    轻量执行与 review 准入¶

    1. 开发前写明受影响的用户路径、预期结果和适用三线场景。小改动复用现有场景，不要求每项一份文档或一个 PR。
    2. 提交 review 时，分别填写三线状态：PASS（必需范围全部通过）、PARTIAL（仅部分已验证）、FAIL、NOT_RUN、N/A。缺环境、没人测试、尚未实现不是 N/A；N/A 仅用于确实无影响的维度，由独立 reviewer 确认理由。
    3. 证据绑定候选 SHA/构建或资产摘要、环境与具体操作；注明自动化/fixture/真实服务/真实用户。后继修改使旧证据失效时仅补测受影响范围。截图脱敏，不含 token、秘密或用户敏感数据；本机路径明确标注，需跨人交接时提供经授权可访问的证据。
    4. Reviewer 聚合阻塞问题与缺失证据，不把作者或 CI 的结论直接复制为三线通过。真实操作错误、假状态、关键操作不可达、用户误解授权/交付结果等阻塞不能仅凭外观正常放行。
    5. 不改变既有合并/发行权限规则。增量研发合并若仍有 PARTIAL/NOT_RUN，必须显式保留缺口、负责人、补验动作及对应交付出口；不得关闭完整 UI milestone 或宣称对应能力已经完成产品验收。完整 UI 能力/版本交付前，三线必需范围必须 PASS，无未解决的阻塞问题。

    无指导可用性测试¶

    • 先说明任务目标、范围和停止条件，不提供点击路线；例：创建并确认任务、判断两个 Worker 如何分工、找到失败原因、理解是否交付成功并取得成果、进入设置后返回原任务。
    • 使用参与者获准操作的真实服务和资源；授权、发布、删除等高风险动作仅在明确允许的隔离目标内进行，不为测试扩大权限。
    • 至少邀请一位未参与该流程开发的目标用户或代表；记录其相关经验与是否接受帮助。人数、场景有限时明确样本局限，不推断普遍易用。
    • 记录每项是否独立完成、耗时、误点、求助、停顿原因、结果理解及失败恢复。观察者必要帮助或安全制止必须留痕，不能仍记为独立完成。
    • 通过条件预先确定：关键任务可独立完成、能正确解释当前状态和交付结果、无关键误操作或阻塞。非阻塞发现入改进清单；修复后对受影响路径复测。找不到用户时如实 NOT_RUN，Agent 走查只能作为补充。

    持续打磨与记录模板¶

    每批次沿用同一份验收记录，集中修复同类问题。复发问题至少补一项可复用措施（回归测试、组件默认行为、设计 token/文案规范或真实用户场景），下批核对是否再次出现；不以新增门禁数量衡量改进。

    功能与可靠性 待填 待填 NOT_RUN 待填
    视觉与交互 待填 待填 NOT_RUN 待填

    另记录独立 reviewer、阻塞/非阻塞问题、修复与复测结果，以及三种不同结论：代码是否可合并、本批哪些能力已验证、完整 UI 是否通过。禁止用一个“review OK”覆盖三者。

    完成定义¶

    全部 P01–P13 有实现与对应证据；下列必需场景通过或明确阻塞，不得用「没实现」跳过必需场景。必须提供一套启用完整能力的受控服务配置，覆盖 P04/P06/P07/P10 和 E10/E13/E18/E31 等全部必需正向流程；501不能替代正向验收。旧profile的未支持行为另跑「正确拒绝/诚实展示」兼容反例，真实Provider支持面单列。

    无 P0/P1 或影响必需出口的未解决缺陷；其他问题逐项记录处置和影响。typecheck/build/相关单元与合同检查通过，既有 required CI 绿。产品/安全双独立审查覆盖同一候选，至少一位独立验收者实际消费已打包安装资产。

    测试层次与样本¶

    1. 组件层：输入边界、状态卡片、主题、键盘；合同样例只用于开发/组件测试，不作为真实服务验收。
    2. 浏览器＋真实 HTTP/SQLite＋受控 Provider：确定性成功、失败、取消、冲突、超时、重连和安全反例，可复现且不消耗真实模型。
    3. 一个已配置的真实 Provider 浏览器完整交付：确认→双 Worker→独立检查→下载后业务核对；第二 Provider 在本次 UI 声明支持时补实测，不重复后端全部历史认证。
    4. 同一发行包安装/静态资源/浏览器接入/旧 API 消费与回滚。新安全入口的检查不能只跑开发 Vite。

    样例固定两类：零 Git 小型报告任务、受支持 Git patch 任务；批准/发布仅用隔离临时目标。失败 fixture 明确标注人为构造，不混入真实模型失误记录。浏览器矩阵为 Chromium 与 WebKit 的自动化场景，以及 macOS Safari 的安装包人工完整冒烟；记录实际版本，WebKit自动化不冒充真实Safari。

    浏览器端不读取 SQLite，但独立测试可在隔离测试环境观察底层次数，证明未重派。

    E2E 场景定义（结果见批次记录）¶

    ID / 对应需求 前置与操作 预期断言
    E01 / P01 UI 开启，导入正确 token；刷新再连接 就绪可见；刷新无持久 token；已有任务可重查
    E02 / P01 错 token、可观察未就绪响应、服务不可达 区分401/就绪响应/连接失败，不能猜无Provider等未启动原因，401停轮询
    E03 / P02 超过一页任务，翻页并搜索 opaque cursor 正确；筛选注明已载入范围；无重复项
    E04 / P03 空/超限需求，256 KiB 边界文件，超过32引用 客户端提示与服务器合同一致，错误保留草稿
    E05 / P03 连续双击创建，同请求丢响应 一个逻辑 key/body，零自动替代 Task，未知结果可见
    E06 / P04 零问题任务确认真实计划 不强制问答；仅用户点击后执行，绑定原 revision/digest
    E07 / P04 有问题→答复→新预览→确认 原问题与方案可见，不越过必要确认
    E08 / P04 两标签页持不同版本确认 陈旧页409，保留输入，不能自动替换摘要再提交
    E09 / P05/P08 两 Worker 并行，单个等待 主页面显示真实等待；无关分支继续，未伪造进度百分比
    E10 / P06 运行问题回答并延迟 ACK 分别显示受理/投递/消费；202 不冒充继续
    E11 / P06/P10 题目到期或使用另一 Task 的摘要 到期不可答；串题/串 Task 拒绝，无副作用
    E12 / P07 暂停时已有 Worker 运行，然后恢复 说明只停止新调度；不把 pause 当进程暂停
    E13 / P07 取消单 Worker，旧 profile 返回501 支持面只取消目标；501 不回退取消整 Task
    E14 / P07 取消 Task 与完成竞态 按服务事实显示；不将点击/202当停止确认
    E15 / P09 产生候选、独立拒收及部分成果 候选/部分标识明确；执行结束不显示整体成功
    E16 / P09 最终成果下载并在独立目录消费 ID/ready/长度/摘要及业务内容一致；下载不冒充发布
    E17 / P09 错摘要、越权制品、8 MiB边界 拒绝损坏或错误归属；不落成可信成果
    E18 / P10 完整本机发布授权允许/拒绝两分支 原文无截断；绑定原请求；拒绝不发布，允许后仍观察回执/后验
    E19 / P10 发布已发生但后验失败/unknown 保留原效果，不自动再次发布，不标整体成功
    E20 / P11 断线/504后原请求回执查询或显式原键重放 不换key/CAS，不重复执行；无法确定就显示待核对
    E21 / P11 轮询乱序、重复页、隐藏页、重新连接 旧revision不覆盖新快照；去重、退避、无请求风暴
    E22 / P11 服务正常重启、前端刷新 原事实可重查；每次重连提示核对上次中断操作，不假称找回内存命令，不补发或复活终态
    E23 / P08/P11 usage=null、无日志、501 暂无数据/未启用明确，不填0或空成功
    E24 / P12 浅深主题、1440/1024/375px、200%缩放 主要操作可达，无整页横滚；颜色对比与长内容合格
    E25 / P12 仅键盘完成确认/问答/抽屉操作 无焦点陷阱，焦点归还，标签/错误可读
    E26 / P01 外站Origin、错误Host、null Origin、缺Bearer 所有非法请求拒绝；旧API-only非空Origin仍拒绝
    E27 / P01/P12 检查URL/存储/日志/错误/打包资产 不包含token；断开清理缓存，不串服务数据
    E28 / P09/P12 恶意Markdown/HTML/SVG/外链/远程图 不执行脚本、不自动外传，危险类型只下载
    E29 / P13 安装同一包开启UI、关闭UI、旧Node客户端 静态资源完整、边界按模式生效，旧API行为兼容
    E32 / P01/P13 静态路径遍历、符号链接、未知文件、GET/HEAD、CSP违规 只清单资源可访问，HEAD无正文，越界拒绝，无脚本绕过或宿主路径泄露
    E31 / P06 Leader business请求定向答复，丢响应与串请求 走leader.reply answer分支、原摘要/CAS；202不伪造Worker ACK，串绑拒绝
    E30 / P13 升级后回滚旧包，重新连接 HTML/资源不混版，原数据不清空，不假重建Task

    性能与可观测性目标¶

    本地无生产模型调用的测试环境：1440px、100个已载入Task、详情500条已载入事件；记录OS/Node/浏览器/机器。首屏可交互目标≤2秒（本地资源、服务正常），点击反馈≤100ms；服务返回新事实后前台显示≤3秒；长列表滚动无持续超过200ms阻塞。超过目标须给出 trace 和处置，不以未测宣称通过。服务端已有响应上限与真实模型耗时分开计。

    记录浏览器错误、失败请求code/requestId、轮询次数与最后成功时间；不记录token/正文敏感输入。测试证据含候选SHA、资产digest、用例ID、环境、实际/预期、截图或trace、失败原因与复测记录。

    最终验收报告模板¶

    • 候选/资产/环境：待填。
    • P01–P13 → E01–E32 → 实现位置/证据：逐项填，不合并伪报。
    • 通过/失败/未运行/不适用及原因：待填。
    • 产品审查、安全审查、独立执行者身份与结论：待填。
    • 已知限制、回滚方式、发行资格：待填。
