    v1.0.0-rc.prerelease 历史安装资产验证摘要¶

    为什么不能迁移为 RC1¶

    1. commit=unknown，没有冻结 exact sourceHead、build date、toolchain/profile与 current canonical object。
    2. 旧四平台集合不是 ADR 0068 的 RC1 支持面；RC1 只支持 unsigned Darwin arm64 CLI-only darwin-local-dogfood preview，Linux/server/其它架构不能成为其发布证据。
    3. 旧资产没有 S1′→S2′→Attach/rebind→terminalization 的 fixed CLI authority 链，没有真实 Pi + 独立 ReviewDecision ACCEPTED，也没有同一最终 bytes 的 host viability、canary、安装与恢复闭合。
    4. 当时记录的 lease、ResultIngress、binding 与真实 Pi 缺口是历史快照；其中部分 component 后来已演进，不能继续作为当前权威状态。当前状态只以 v1.0 Release Readiness 判定表 为准。
    5. 旧 lightweight git tag v1.0.0-rc1、git push 后自动发布和旧 version 输出期待均已撤销。ADR0068要求的RC1 carrier、canary receipt、tag publish与installer guard仍未实现；在这些后续切片落地并经审查前，不得创建tag、不得发布，也不得把本地candidate称为可用RC1。

    当前已实现的单资产构建合同¶

    make dist-rc1 是ADR0068 build-once路径的第一个本地构建切片，不是发布入口。它与原有make dist四平台合同分离，并只接受以下精确输入：

    • VERSION=1.0.0-rc1；
    • 40位小写Git commit COMMIT；
    • UTC秒级BUILD_DATE；
    • go.mod 锁定的精确Go toolchain。

    dist-rc1 的 DIST_DIR 必须是尚不存在的新目录；命令拒绝覆盖、清空或复用已有目录，避免把第二次构建伪装成同一candidate。普通stable dist继续保持清空并重建已有DIST_DIR的原语义。

    输出目录必须且只能包含：

    1. marshal_1.0.0-rc1_darwin_arm64，其selfProfile=darwin-local-dogfood；
    2. exact 8-line RELEASE-MANIFEST；
    3. exact 2-line SHA256SUMS。

    verify-rc1-dist要求调用方同时提供expected sourceHead、buildDate、goVersion、OS、architecture与profile，manifest不能用自身字段充当外部期望值。校验器不执行candidate：固定Go工具的version -m证明goVersion、cmd/marshal、exe/gc、CGO_ENABLED=0、GOOS=darwin、GOARCH=arm64、-trimpath=true、无VCS settings；有界只读Mach-O解析器再读取实际buildinfo.version/commit/buildDate/selfProfile符号并逐项比对。为此RC1保留符号表但继续去除DWARF；缺符号、shell fixture、错误Mach-O header或真实binary identity漂移均fail closed，candidate本身不会被执行。

    SHA256SUMS只接受64位小写hex、两个逐字ASCII空格和固定文件名；uppercase、tab、单空格、前后空白、重复或乱序均拒绝。任何Linux、amd64、stable、其它RC、符号链接或额外文件也继续拒绝。

    该合同只冻结单个candidate的本地bytes和构建元数据，不产生canary、ReviewDecision、ACCEPTED、carrier、tag或publication authority。后续workflow必须消费这一对象，而不是在tag job中重建一份“等价”binary。

    当前迁移入口¶

    • RC1 范围、partial supersession、same-bytes 与 negative claims：ADR 0068。
    • 当前成熟度、剩余顺序与发布阻塞：v1.0 Release Readiness 判定表。
    • 当前用户安装行为与“RC1尚不可安装”声明：安装、升级、回滚与卸载。
