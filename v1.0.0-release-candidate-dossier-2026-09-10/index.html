    5. ENOSPC 处置（按既有 EFBIG 证据，不新增 OS 层推导）¶

    维护者决议按既有证据处理：既有 SQLite 页数上限 FULL（实测页数 38 的 SQLITE_FULL）与 storage-write-failure 的受控 I/O 失败有界回滚证据成立；真实 OS 盘满不在本轮执行（本机无 root，无法安全地提供独立小容量 fs，且不对共享宿主的盘做破坏性填充）。ENOSPC 作为既有 EFBIG 证据的边界项如实留档，不作为 stable 声明的一部分，也不据此推导后续等价。

    6. 放行前执行清单（状态就绪，执行项由决策者启动）¶

    1. ADR 0096 独立 review 关闭并合入（发布权限变更必经 ADR）。
    2. minisign 公钥列入仓库（docs/RELEASE-PUBLIC-KEY.minisign.txt，本文件另按选定位置建），私钥维护者持有不入仓。
    3. 受保护 annotated tag v1.0.0 → fc2cdc9298c3e1aaf47615373bb24e6d80e4c719，推送至远端。
    4. minisign -S 签名：manifest 摘要行与运输 ZIP 行（输出清单 SHA256SUMS 与 SHA256SUMS.minisig）；用 ADR 0096 §1 三级互证公式公开比对。
    5. gh release create v1.0.0：附 SHA256SUMS + SHA256SUMS.minisig + 公钥原文 + 本 dossier；notes 引用 Roadmap 当前表,受保护仅主流路径。

    以上均为确定性小步操作，不代替既有门禁；发行成功校验 = 三级互证全绿 + 以下载外部新装的验签公式通过。

    7. 收窄不说（不随放行消灭）¶

    • usage=null（模型用量）仍为未知，不改写。
    • trueProcessOverlapProven=false 仍为当前真值（本候选轮次未证明原进程交叠）；文本耗时/HTTP 观察不冒充进程交叠。
    • 12 个 /usr/bin/git 写死用例由 ubuntu CI 承接；该边界说明不改变：在部署环境不存在 /usr/bin/git 时，产品运行依赖配置项提供既有 git 可执行路径。
    • production=false / ordinaryUser=true 口径维持；本 dossier 不授予生产授权，也不是社区公证或替代签名。
    • 企业级签名/notarized/CD 不属于本 dossier 范围。
