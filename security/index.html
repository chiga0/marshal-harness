    安全与隐私¶

    Marshal 会运行能够读取代码、修改文件和执行测试的 Agent，因此安全不是一个开关，而是任务范围、执行隔离、凭据管理、独立验证和发布控制共同形成的边界。

    默认安全原则¶

    • Agent 只获得完成任务所需的最小权限；
    • 编码 Agent 默认拿不到发布凭据；
    • 每个写任务使用独立工作区，不直接修改主 checkout；
    • Agent 的完成声明不能替代独立验证；
    • 验证失败、证据过期或状态不确定时停止推进；
    • 发布前重新确认当前代码与已审查结果一致；
    • 默认只创建 Draft PR，不自动合并；
    • 失败和中断同样留下结果记录。

    当前本地版本能保证什么¶

    本地版本主要防止误操作和流程绕过：它隔离任务工作区、过滤传给 Agent 的环境变量、分离执行与发布凭据，并在发布前检查真实代码和测试结果。

    这些措施不等于恶意代码隔离。普通本地子进程仍可能接触同一用户能够访问的文件、系统凭据或网络服务。不要用当前本地模式运行不可信仓库、依赖或构建脚本。

    何时需要强隔离¶

    以下场景应使用容器、虚拟机或具备可验证隔离能力的远程 Sandbox：

    • 仓库或依赖来源不可信；
    • 任务需要长时间无人值守；
    • 多个用户共享同一执行平台；
    • Agent 可以访问网络、云资源或生产系统；
    • 法规或组织政策要求明确的文件、网络和资源隔离。

    Marshal 的目标是让不同 Sandbox 接入同一控制流程，并在环境无法满足任务要求时拒绝执行。Cloudflare Sandbox 是计划支持的远程选项之一。

    凭据如何处理¶

    执行代码和发布代码使用不同身份。发布凭据只在发布阶段交给专用组件，不写入任务描述、Agent 提示词或普通日志。

    用户仍应使用权限最小、可撤销、短有效期的凭据，并为测试和生产环境使用不同身份。

    会保存哪些数据¶

    当前本地版本会在目标仓库被 Git 忽略的 .marshal/ 目录中保存任务状态、日志、代码差异、测试结果、审查结果和发布记录。这些数据用于恢复与审计，不应提交到业务仓库。

    任务描述、日志和生成物可能包含源码或业务信息。使用第三方模型、远程 Sandbox 或云存储前，请同时检查对应服务的数据处理政策。Marshal 不会替代这些服务自身的隐私和合规承诺。

    安全问题上报¶

    请不要在公开 Issue 中提交漏洞细节、凭据或私有日志。安全问题请按照仓库的 SECURITY.md 私下报告。
